# maps

地图组合层，说明见 [README](README.md)。两个 MCP 工具的逻辑在 `app/tools.py`（编排、参数、结果）和 `app/resolve.py`（地名怎么定），说明和给模型的文字在 `app/mcp_server.py`，两家客户端在 `app/amap.py`、`app/tmap.py`，转不转、额度记忆、用量在 `app/upstream.py`。

- key 只拼在请求参数里：httpx 的请求行带 key，日志一律压到 WARNING；地名、关键词、坐标不进日志。
- 只请求客户端里列出的固定路径，不跟随重定向、不重试。
- 转不转按每一次上游请求判断；“上游拒了这次请求”和“查到 0 条”不转。改分类（`classify`）要先看两家文档里的错误码，别把参数错误归成可转的，会白耗另一家的额度。
- 以 Fusion 为底：比 Fusion 少做的先查原因；Fusion 踩过的坑（重名、按 1 公里合并候选、坐标进结果、出发时间当真）不要再踩。改结果字段或说明会影响两个产品的模型和页面，要同步 README，并告诉两边。
- 给模型看的说明（英文）不点名别的工具、不提卡片、不写工具自己的名字、不提服务商；产品专有的话由产品接在后面。
- 测试用 `tests/fixtures` 里录好的响应，不打真实接口；要补样本就用真 key 录一次，去掉折线，确认文件里没有 key。
- 两把 key 都没配也照常启动，工具回“查不到”。
